# Bringing chats from another Neconyan instance

I keep origin and seal checks on by default because an old copy of a chat shouldn't replace newer history. If you're moving a character and its chats between installations, use 'Import as new instance' to adopt a separate copy.

Open Characters → Import. Import the character card first, or select a character you already have. Under 'Bring your chats too', check the selected character, tick 'Import as new instance', then choose 'Import chat files'. Select all the JSON or JSONL files for that character together. You can choose up to 64 files; the combined upload must fit within 64 MiB.

The same unchecked option is available in Chat History → Import from another instance, followed by 'Import Chat'. Leaving it off keeps the normal origin and seal checks. A refusal doesn't turn adoption on for you.

Adoption creates one new character instance and a separate chat folder, even when you already have a character with the same name. Each imported chat gets a fresh identity and seal from this installation. The existing character and its history stay intact, and message dates don't decide which history survives.

It's one-way. The new copy has no continuity link to the source installation. Links to source branches and checkpoints, cached chat identities and inherited Mewmory records aren't carried over. Message text, alternate replies and reasoning are retained. Normal ghost-writer protections apply to later saves and replies, so a stale page still can't replace newer history.

If an upload loses its response, select the same source character, explicitly tick the option again and choose the same files. The saved retry identity resumes that import instead of creating another copy. Group imports don't offer adoption; select a character if you want to adopt those exported messages into a separate character instance.
