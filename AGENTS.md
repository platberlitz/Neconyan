# Working on Neconyan

Read `PRODUCT.md` (what it is, who it is for, tone) and `DESIGN.md` (tokens, type, phone rules) before touching UI.

UI work, in short:

- Stability, performance and device fixes must preserve the normal layout, including control sizes, spacing and row placement. Scope any necessary layout fallback to the failing state, such as a short screen with the keyboard open. Ask before changing the normal design. Compare before and after in the browser; do not update a layout test merely to accept an unrequested change.
- Design for what the user actually works with: the chat, the composer and the task on screen get the space and the first tap; rare settings step back (see 'Design for what people actually use' in `DESIGN.md`).
- Buttons are accent-aware: fills, borders and states come from `--neco-ginger`/`--neco-ginger-hover`, text on an accent fill uses `--neco-on-accent`, and no button carries a hex colour (see 'Accent-aware buttons' in `DESIGN.md`).

## Test and check commands

- Unit tests (Jest, 300+ suites): `npm run test:unit --prefix tests`. Use Node 24. On a machine with limited memory the full run can run out of memory, so cap it: `NODE_OPTIONS=--max-old-space-size=4096 npm run test:unit --prefix tests -- --maxWorkers=2 --workerIdleMemoryLimit=512MB`.
- Single suites: `npm run test:unit --prefix tests -- <pattern>`. Plain `npx jest` fails every suite because it skips `--experimental-vm-modules`. Patterns match the full path, including the checkout folder name (a `mewmory` filter in a `mewmory-*` worktree runs every suite), so use `--runTestsByPath <file>.test.js` (relative to `tests/`) for exact files.
- Suites that `jest.unstable_mockModule` a core module with a partial export list fail at link time ('does not provide an export named X') as soon as that module or one of its importers needs a new export. Put new core-facing APIs in a small dependency-free module beside the core file (as `public/scripts/world-info-policy.js` does), or add the name to every such mock (for example `tests/in-chat-agents-runner.test.js`, and `tests/in-chat-agents-pre-intercept-summary.test.js`, which mocks `utils.js` and `constants.js` with only a few exports). `public/lib.js` cannot load under Jest; macro tests mock it with `jest.unstable_mockModule('../public/lib.js', () => ({ chevrotain }))` and import the lexer and parser dynamically (see `tests/macro-comment-pipes.test.js`).
- Run the full Jest suite, the Node suite and browser tests one after another, not at the same time. Running them together causes timeouts in unchanged tests. A timeout seen only in a combined run is not a regression until it also fails when run on its own. `tests/jobs-client.test.js` is timing-sensitive and can fail under load; rerun it alone before blaming a change.
- Node tests for server modules: `node --test tests/*.node.js`
- Lint: `npm run lint` (root), `npm run lint --prefix tests` (tests folder, not in CI)
- Frontend budgets: `npm run check:frontend-budgets` (blocking CSS bytes, script count and size)
- E2E (needs a running server): from `tests/`, `NECONYAN_TEST_BASE_URL=http://127.0.0.1:PORT npx playwright test <file> --reporter=line`. Several suites fail in a preview without an API key; compare against the baseline before blaming a change. Run `neconyan-agents-workspace.e2e.js` with `--workers=1` (its tests edit the same data). Suites built on `tests/neconyan-conversation-durable-fixture.js` start their own server and need `NECONYAN_CONVERSATION_TEST_DISPOSABLE=1` instead of a base URL.
- Probing a running server that uses basic auth: use `node:http`/`node:https`, not built-in `fetch`. `fetch` sends a `Sec-Fetch-Mode` header, so the auth middleware returns 401 even with correct credentials.
- Local preview that serves `public/` live: `node server.js --configPath <config> --dataRoot <data> --port <port> --browserLaunchEnabled false`. With `performance.frontendBuild.enabled: true` the server serves the hashed build in `dist/frontend` instead, so either run `npm run build:frontend` or disable that flag while iterating.
- Translations: `node scripts/build-interface-locales.js` inventories UI strings; `--list` prints the keys and `--write-catalogue` refreshes `public/locales/neconyan/en.json`, neither touching a translator. Set `NECONYAN_TRANSLATION_COMMAND` to a translator command to fill `public/locales/neconyan/<lang>.json`, and `NECONYAN_TRANSLATION_LANGS=pt-pt` (comma-separated) to fill one language at a time. Coverage audit: `node --test tests/locale-coverage.node.js`.
  - Do not commit `--write-catalogue` output in a feature change: the committed catalogue lags the code, so it pulls in hundreds of pending strings from other work and reorders the file. Use `--list` and add only your own keys to `public/locales/neconyan/en.json` by hand, each mapped to itself and placed beside related strings. That file is `JSON.stringify(data, null, 2)` plus a newline, so parsing, splicing and rewriting it gives a minimal diff. English-only additions pass the coverage audit. On a merge conflict in `en.json`, merge staging and rerun the builder rather than resolving by hand; key order differs between machines, so compare key sets.
  - Never parse and re-dump the other locale files: `th-th.json` uses its own indentation and `ru-ru.json` has duplicate keys, so re-serialising reformats them or silently drops entries. Append text in the file's own indent, then parse before and after to check that only the intended keys changed.
  - `public/scripts/ui-localization.js` translates visible text by exact trimmed match against the merged dictionaries and skips user content (`.mes_text`, `textarea`, `[data-i18n-ignore]`), so rewording an English caption orphans its translations. Locale checks: `node --test tests/interface-locale-catalogue.node.js tests/locale-coverage.node.js tests/locale-branding.node.js tests/locale-composed-captions.node.js`, plus `tests/ui-localization.e2e.js`.
  - `tests/locale-builder-collection.node.js` (Node runner, not Jest) fails when a collected string has placeholders touching or only whitespace apart, such as `${a}${b}`. Join the parts with `[a, b].filter(Boolean).join(' ')` or keep a literal word between them. Interpolated template-literal `aria-label`s are not inventoried.
- More E2E setups: `tests/mewmory.e2e.js` skips unless `NECONYAN_MEWMORY_TEST_DISPOSABLE=1`, needs `NECONYAN_TEST_BASE_URL` pointing at a disposable server using the fixture provider `node tests/mewmory-provider.js` (see `docs/mewmory.md`) and `--workers=1`. `tests/ui-localization-panels.e2e.js` also needs `--workers=1`, because concurrent settings saves raise the 'Settings changed on another device' dialog. The shell restores the last-selected left-drawer tab at startup, so select another tab, close and reload before trusting a 'panel not loaded' result.
- A fresh Playwright context with basic auth enabled can sit on the login page (`body.login`) and never emit `neconyan:ready`. Check the URL and body class before calling it a startup hang, and read `pageerror` before blaming a slow cold start.
- Durable-fixture suites compile webpack on first start, which can exceed the fixture's 60 s readiness wait, and the cache key includes the checkout path. Precompile with Node 24 and set `NECONYAN_TEST_LIBRARY_CACHE=<dir>/_webpack` (a separate cache for a baseline checkout). Select tests with `-g 'A|a'`, not a case-insensitive grep that picks unintended titles.
- `page.waitForFunction(async () => ...)` returns as soon as the predicate returns a promise, so async predicates pass falsely. Use `await expect.poll(() => page.evaluate(async () => ...)).toBe(true)`.
- 'Execution context was destroyed' with no navigation can be Chromium's 'Promise was collected' on a long `page.evaluate`. Start the work synchronously, keep its completion state on the page and wait for that state (see `tests/nanogpt-controls.e2e.js`) before treating it as an app reload bug.
- `selectOption` with a value that no longer exists retries until the test times out; check the live options first.
- The Agents list and template library redraw on a 200 ms debounce, so wait for the filtered count before clicking (`tests/in-chat-agents-e2e-helpers.js`). In Mewmory settings, fill number fields before controls that save immediately.
- Assistant help topics in `public/scripts/neconyan-assistant-knowledge/*.js` quote exact UI strings as anchors, and `tests/neconyan-assistant-knowledge.node.js` (Node runner, not Jest) fails when one disappears. When renaming a visible label, grep the knowledge files for the old wording, update the topic and add retrieval cases in `tests/neconyan-assistant-knowledge-cases.js`.
- Jest suites that slice functions out of browser source into a `vm` with stubs (`pathfinder-generation-wiring`, `shell-style-persistence`, `neconyan-stage-b`, `scratchpad-context-refresh`) fail with `ReferenceError` when the sliced code calls a new helper; add a stub. Run `shell-style-persistence.test.js` whenever `setShellTheme` changes. `tests/user-text-render.e2e.js` silently skips names it does not know, so new module-level state joins its `wanted` list.
- `src/prompt-converters.js` reads config at import: mock `src/util.js` first, or import it dynamically after `setConfigFilePath`. Make temp files with `path.join(os.tmpdir(), 'prefix-')` and keep a disposable `--dataRoot` outside the repo (`.gitignore` covers only `/data`). File-identity tests (device and inode) create the replacement before unlinking, then `renameSync`.
- Mock chat providers need SSE that ends with `data: [DONE]` plus `GET /v1/models` (see `tests/mewmory-provider.js`). Bundled opt-in extensions stay off on fresh profiles unless `extension_settings.bundledOptInProcessedExtensions` lists them. `#qig-setup-wizard` intercepts clicks on fresh profiles; dismiss it with `page.addLocatorHandler`. `neconyan-android-update.e2e.js` needs `NECONYAN_TEST_BASE_URL`.
- Scripted POSTs need the session cookie from `GET /csrf-token` plus the `X-CSRF-Token` header (Node `fetch` keeps no cookies). `POST /api/settings/save` is version-guarded (409 `settings_conflict`), so screenshot scripts cannot fake saves with `{ result: 'ok' }`; use a throwaway data root. Mock saves with `route => acknowledgeSettingsSave(route)`, never by passing the helper directly.
- Previews: before reusing a running preview, check which checkout it serves by fetching a changed asset and looking for your change. Otherwise start your own on a free port with a disposable config and data root, and stop it with `fuser -k <port>/tcp`, not `pkill -f`. A killed preview can linger and hold its data-root lease (`DATA_ROOT_OWNED`), so start again with a fresh data root. `neconyan-agents-workspace.e2e.js` expects a fresh data root.
- A new browser context replays the tour on Home: wait for `.neconyan-home-booting` to clear, click `#neconyan-tour-coachmark [data-tour-coach-skip]` and hide `#nn-update-toast` and `#toast-container`. On a fresh data root Quick Image Gen first-load warning toasts can cover the point `neconyan-cat-motion.e2e.js` touches above `.neconyan-home-intro` (the test hides only the update toast).
- Settings are tabbed (`neconyan-settings-tabs.js`): click `.sb-settings-tab-btn[data-tab=...]` (phones: `select.sb-settings-category-select`), then the section's `.inline-drawer-toggle`. Phone and desktop outlets both exist in the DOM, so scope selectors.
- Theme and accent tests: set accents by dispatching `new CustomEvent('change', { detail: { rgba } })` on `#sb-accent-primary-picker`/`#sb-accent-secondary-picker`, or by clicking `.sb-accent-preset[data-accent=...]`; setting `--SmartThemeQuoteColor` alone does not recompute `--neco-ginger`. Pale and dark samples: Mint Glass `rgba(110,231,183,1)`, Plum Wine `rgba(126,34,206,1)`. Sample colours after `settleCssTransitions(page)` (`tests/chat-scroll-regression-helpers.js`) and compare `color-mix` results by painting a 1x1 canvas, cleared between samples. Theme and accent changes rebuild preview nodes, so query and measure synchronously inside one `page.evaluate`. Release groups share one preview account, so tests that change Shell Style or theme restore Calico in `finally` and wait for the save. In disposable previews, themes can also be switched by editing `<dataRoot>/default-user/settings.json` between runs (theme name plus the legacy colour keys from `NECONYAN_CALICO_THEME_FALLBACK`/`NECONYAN_CALICO_DARK_THEME_FALLBACK`).
- Streaming and timing: `STREAM_TOKEN_RECEIVED` fires before `onProgressStreaming` writes `.mes_text` (throttled by `streaming_fps`), so observe `.mes_text` itself. Chromium never returns `longtask` from `getEntriesByType`; use a `PerformanceObserver` as `scripts/measure-frontend-performance.js` does. Measure layout after paint: `requestAnimationFrame`, then a `MessageChannel` message.
- Full-account import tests keep the page open, include `settings.json` and trigger a delayed settings save (`tests/application-import.e2e.js`, `tests/account-import-settings.test.js`).
- `tests/neconyan-native-extensions.test.js` fails if any file in a bundled extension folder is untracked; `git add -N <file>` new files. `public/scripts/extensions/third-party/*` matches `.gitignore` even though its files are tracked: `git add` there prints 'paths are ignored' and exits 1 while still staging tracked files, so do not chain it with `&&` or `set -e`, and new files need `git add -f`. Root lint ignores `third-party/**`.

## Browser CI rerun scope

- Choose the rerun scope from what changed. Preserve passing shard results (a shard is one test group); an isolated failure isn't a reason to restart the whole suite.
- With no code changes, inspect the failure first. If the evidence supports an intermittent failure, rerun only failed jobs with `gh run rerun <run-id> --failed`.
- After an isolated test fix, run the affected tests or shards against the new commit. GitHub's failed-job rerun reuses the original commit and cannot validate later fixes. A new commit alone doesn't justify another full run.
- Use a full rerun when application behaviour, shared test setup or workflow changes have broad or uncertain effects. State the reason before starting it.
- If a failure repeats, return to diagnosis before another retry. Keep the logs and distinguish a corrected test from an unchanged test that passed on retry; don't weaken assertions or skip failures to get a green result.
- Playwright retries failed browser tests once in CI. The release run's summary lists tests that passed on retry as flaky, separately from unresolved failures. Download `release-e2e-diagnostics-*` for the first failed attempt's action trace, screenshot and video when available, even if the job is green. CI traces omit DOM snapshots and the trace filmstrip for speed. `release-e2e-result-*` records outcomes and durations.
- The nightly staging run is scheduled for 03:17 UTC once the workflow reaches the default branch. It resolves the exact staging commit, skips an unchanged complete run and tries incomplete runs again the next night. The 'Nightly staging browser checks' issue tracks failures, flakes and PRs merged since the last first-attempt-green night. The workflow opens one issue per test that flakes on consecutive complete nights; an unchanged night doesn't count as a run. The last clean night's measured timings are saved as an artifact and used to balance subsequent nights, without pushing commits. The scheduled run doesn't replace the release gate. For a dry run, dispatch with `-f nightly_preview=true`; this never updates the issues or saved timings.
- Pull requests run a short browser check on GitHub's test merge commit: Catline icons, opening Conversation and Roleplay on phone and desktop, and the mobile composer's normal layout and keyboard fit. Changed `.e2e.js` files that fit another two estimated minutes are also included. The job summary lists every selected file and any changed file it couldn't cover. Dispatch a focused release-browser run for long files, crash checks and Edge; use the dedicated fixture for Mewmory. The PR check doesn't replace full coverage. Update its Noble Playwright image pin along with `release-e2e.yml` and `tests/package-lock.json` when upgrading Playwright.
- Record the commit and scope each result covers. Reuse unaffected results honestly and state what still needs checking, rather than repeatedly spending an hour on the entire matrix.

## CSS shipping rules

- Blocking stylesheets share a 1 MiB budget and sit within a couple of KiB of it. Delete dead rules before adding; the phone-gated sheets (`mobile-styles.css`, `neconyan-paper-theme.css`, `neconyan-mobile-shell.css`) do not count towards bytes. Non-critical styles can go in a deferred sheet instead (`<link rel="preload" as="style" data-sb-deferred-style data-sb-media="all">` in `public/index.html`, as `neconyan-menus.css` and `neconyan-help.css` do); budgets ignore it, but a new sheet with transitions must be listed in `tests/ui-motion-css-compliance.test.js`.
- `!important` counts are capped per sheet by `tests/mobile-css-budgets.test.js` and are at the ceiling in `neconyan-mobile-shell.css`, `neconyan-tabs.css`, `neconyan-theme.css`, `neconyan-paper-theme.css` and `neconyan-chat-styles.css`. Win with specificity, not `!important`. `neconyan.css` and `neconyan-calico.css` are unbudgeted for the count but blocking for bytes.
- No `//` comments in CSS. Use `/* */`.
- Phone-only rules go in `neconyan-mobile-shell.css`; both-viewport rules in `neconyan.css`; Calico palette and cat decorations in `neconyan-calico.css`.
- Some sheets load after the core ones: extension `style.css` files, `neconyan-conversation.css`, `world-info.css`, `personas.css`. Overrides need one more id or class than the rule they beat.
- Every CSS change ships with a cache bump: `NN_SW_CACHE_VERSION` in `public/sw.js`, `NN_SHELL_STYLE_STYLESHEET_VERSION` in `public/scripts/neconyan-tabs.js` and every stylesheet `?v=` query in `public/index.html` (core, theme, paper, mobile shell, deferred sheets, shell-style and kittyless loaders) move to the same value. Webfont, image and icon-sheet (`neconyan-icons*.css`, pinned by `tests/catline-icons.test.js`) `?v=` strings are pinned by tests; leave them. `tests/character-tag-manager.test.js` also holds the cache version as a literal; update it, then rerun `character-tag-manager`, `character-purrks`, `device-sync` and `character-tags-accent`.
- After rebasing onto staging, compare `public/sw.js` with staging's copy. If staging already uses the same cache version, the rebase applies cleanly but your bump does nothing; bump again.
- Known cascade traps:
  - `public/css/shell-styles/windows-98.css` sets `transform: none` on every `.menu_button`. Position buttons with the separate `translate:` property, not `transform: translate...`.
  - `#left-nav-panel select` has `z-index: var(--sb-z-raised)` (10). Dropdowns and popovers inside left-panel pages need 11 or more, or a select shows through them.
  - Chat message HTML is sanitised by DOMPurify: every class gains a `custom-` prefix (except `fa-*`, `note-*`, `monospace`), so CSS targets `.custom-<class>`, and HTML that will be sanitised must use the plain class name.
  - Custom properties resolve where they are declared. `neconyan-theme.css` derives the `--sb-chat-surface-*` chain from `--sb-chat-surface-source` on `:root`, so an override on `body` must redeclare the whole chain; the phone shell surfaces (`--sb-mobile-default-surface-solid` and friends) are also `:root` values.
  - Real tokens are `--neco-surface`, `--neco-raised`, `--neco-ink` and `--neco-muted`. `--neco-bg-elevated`, `--neco-bg-panel`, `--neco-text-main` and `--neco-text-muted` do not exist. `--neco-ink` and `--neco-surface` swap with the surface tone (`:root[data-sb-surface-tone='light'|'dark']`, `data-sb-text-tone`), so a decoration that must stay dark starts from a fixed dark colour mixed with `--neco-ginger`, not from `--neco-surface`.
  - The Calico palette gives every `[aria-pressed='true']` a 15% ginger mix; beat it with the component's root id. On phones the paper theme forces `border-radius: var(--neconyan-control-radius, 14px) !important` on drawer and popup inputs and buttons; set `--neconyan-control-radius` instead of fighting it.
  - The Echo chat-style family pins `--charNameFontSize` and a 15px `--messageTextFontSize` with `!important`. A `vw` term inside a `clamp()` font size defeats the font-size slider.
  - Send and composer buttons: `neconyan.css` styles `:is(#send_but, #sb_conversation_send)` from `--sb-send-bg`, `--sb-send-ink` and `--neconyan-control-radius`; restyle through those variables and draw borders with an inset `box-shadow`. The Calico rule for `#leftSendForm` icon buttons is specificity (3,1,2), so an override needs something like `body #send_form #leftSendForm > div#my-button.interactable`. `#send_but` stays hidden until a model is connected (force it visible in probes), and the visual order of composer buttons differs from DOM order, so measure x positions.
  - In nnchat chat styles the sleeping cat's position is written inline by `public/scripts/neconyan-message-sleepers.js` (`--nnchat-sleeper-top`/`--nnchat-sleeper-left`); change `sleeperPlacement()`, not CSS. On phones `neconyan-paper-theme.css` forces `.mes` padding for the other styles, and `neconyan-theme.css` gives `.mes[is_user='true'] .mes_block` an outline, padding and tint that self-carded styles (Echo, Whisper, Hush, Tide, Compact) reset.
  - Compact Mode (`html[data-sb-compact-mode='true']`) lives in the deferred `public/css/neconyan-compact-mode.css`. Phones trim spacing only, never tap-target size; size changes stay inside `@media (min-width: 1001px)`, pinned by `tests/compact-mode-everywhere.test.js`.
  - In `public/scripts/extensions/in-chat-agents/style.css` the `@media (max-width: 768px)` block comes before the base `.ica--companion-*` rules, so a phone rule of equal specificity loses. Add one more class rather than reordering the file.
  - The character editor is rearranged at runtime: `ensureCharacterEditorLayout()` in `public/scripts/neconyan-tabs.js` moves description, personality and tags into Basics, prompt overrides into Advanced and the back and create buttons into the commit bar. Check the live DOM before styling it.
  - `windows-98.css` also paints every `i` inside `.sb-shell-header` with caption ink, so icons there need `:not(:is(.menu_button, .sb-shell-close) *)`. Preview it with `localStorage['sb-theme'] = 'windows-98'` plus a light theme.
  - `:root[style*='--mainFontFamily']` in `neconyan.css` switches headings to the body font, so no other inline style value on `:root` may contain the text `--mainFontFamily` (see `GOOGLE_FONT_ROLES` in `public/scripts/power-user.js`).
  - `neconyan-theme.css` boxes `h3:not(.popup h3):not(#chat h3)`, so an `h3` in a popover appended to `document.body` picks that style up. `style.css` draws its own `::-webkit-search-cancel-button`; hide it when adding a custom clear button.
  - `.menu_button:not(.disabled):not([disabled])` (0,3,0) in `neconyan-theme.css` overrides extension button backgrounds. Under Calico `dialog.popup` is 90% translucent, so a popup that needs a solid body gives `.popup-body` `--neco-surface`.
  - Character card CSS: `decodeStyleTags` prefixes selectors with `.mes_text` and classes with `custom-`, so selectors such as `#chat` cannot match. Echo, Whisper, Hush, Ripple and Tide set paragraph styles at id weight with `!important`, so card CSS overrides `--messageTextFontSize`, `--messageLineHeight` and `--mesParagraphSpacingTop`/`Bottom` on the card root. Regex replacements expand `$1`, `$<name>` and macros, so generated CSS must not contain them or `{{`.
  - In Jest, `formatCompanionContent` adds no `custom-` prefix because the DOMPurify hook is absent: unit tests assert plain class names, browser tests `custom-` names.
  - `tests/css-root-has-selectors.test.js` rejects new root `body:has(...)` selectors; reuse an allowed pattern such as `body:has(.drawer-content.open) #top-settings-holder:has(...)`.
  - `tests/mobile-css-budgets.test.js` caps distinct media-query pixel breakpoints at 18; reuse an existing breakpoint.
  - `revealUi` and `setUiVisibility` (`public/scripts/ui-motion.js`) animate `translate` unless passed `{ distance: 0 }`; surfaces positioned with `translate` (such as the Input History menu) must pass it.
  - On phones `syncMobilePopupKeyboardShift` (`neconyan-tabs.js`) keeps `dialog.popup` above the keyboard and drops the bottom safe area while it is open. Full-screen phone sheets opt in with `--sb-popup-fills-screen: 1` (the Agents editor and Chats archive do).
- `mewmory.css` is a deferred sheet but is also loaded by script (`loadMewmoryStyles` in `public/scripts/mewmory/ui.js`); a cache bump updates both. Docs reader pages (`/docs/:slug`, `src/docs-reader.js`) carry inline CSS and need no cache bump; `ASSISTANT_ART_VERSION` there must match `ART_VERSION` in `public/scripts/neconyan-assistant-art.js`.
- A merge conflict that touches only cache-version labels resolves to the branch's own labels; then check the rebase rule above.
- A floating element appended to `document.body` beside a drawer (tour cards, popovers) closes that drawer when pressed unless its selector is in `forbiddenTargets` in `public/script.js`.
- New `transition`/`animation` declarations need a reduced-motion guard. Guards cover both `prefers-reduced-motion` and the app's own `body.reduced-motion` setting. Reduced-motion rules on universal selectors use `transition-duration: 0s`, never `0.01ms`, which made long phone replies about ten times slower.
- Horizontal rails on phones need `touch-action: pan-x` plus an entry in `MOBILE_DOCUMENT_PAN_HORIZONTAL_SCROLL_SELECTOR` (`public/scripts/mobile-shell-lifecycle/index.js`) and the matching row in `tests/mobile-shell-lifecycle-wiring.test.js`.

## Verification standard

- Reproduce before fixing: read the cascade or the code path end to end, then change the one place all callers route through.
- Verify in a browser, not by reading alone: drive Chromium (the Playwright copy in `tests/node_modules`) at 393x852 with touch for phones and 1280x900 for desktop, and measure computed styles and geometry. iOS behaviour verified this way is inferred and must be labelled as such.
- Real WebKit (Safari's browser engine) is also available through Playwright and catches what Chromium hides, such as timing, animation and layout behaviour that differs between Blink and WebKit. If it fails to launch with missing libraries, install them once from `tests/`: `sudo env PATH="$(dirname "$(command -v node)"):$PATH" npx playwright install-deps webkit` (with Node 24 on `PATH`). Then use `require('@playwright/test').webkit.launch()` in place of `chromium`, headless, or headed under `xvfb-run -a -s "-screen 0 1400x1000x24"`. The iOS helpers below work with it, but `applyIOSOnlyCss(page)` is still needed because desktop WebKit does not support `-webkit-touch-callout` either. WebKit on Linux can be slow (a few frames per second in the full app), so judge smoothness from a small page that loads the real module, and use the full app for logic and timing traces. It is still desktop WebKit on Linux, not an iPhone, so label results as inferred for iOS.
  - The full app runs at about 2 fps in Linux WebKit because of `backdrop-filter`; for motion comparisons inject `backdrop-filter: none` into both builds and say so.
  - Linux WebKit can hold back part of a streamed SSE response until the next write (about 1 KB events arrived roughly 500 ms late; Chromium was fine). Compare a tiny streaming page and an independent HTTP reader before blaming CSS or relaxing assertions.
  - WebKit starts a Web Animation's clock when `element.animate()` is called, Chromium at first paint, so synchronous work after `animate()` eats the start of the slide. `play()` in `public/scripts/ui-motion.js` resets `currentTime` on the first frame; use `ui-motion` rather than raw `animate()`.
  - An opaque `srcdoc` sandbox returns an empty `document.cookie` in WebKit but throws in Chromium.
- For anything an iPhone user reports, emulate iOS with `tests/ios-safari-emulation.js`: `IPHONE_SAFARI_CONTEXT` + `installIPhoneSafari(context, { standalone })` spoof the user agent, `navigator.platform`, touch points and home-screen mode (so `body.safari`, `body.PWA` and `isIOSWebKitPlatform()` behave as on a phone), and `applyIOSOnlyCss(page)` re-applies the `@supports (-webkit-touch-callout: none)` / `-webkit-overflow-scrolling` rules Chromium skips. Call it again after late sheets such as `world-info.css` load. Those rules lift the right-hand drawers to `--sb-z-popout` (4000), so floating UI that looks fine in plain Chromium can sit hidden underneath on iPhones. `applyIOSOnlyCss` appends the copied rules after every sheet, which can change cascade order and cause false failures (seen with movable panels); check the order before blaming the app. `Element.checkVisibility` needs Safari 17.4 or later; guard it with a `getClientRects().length` fallback (optional chaining on the element does not guard a missing method).
- On iOS, popovers with their own scrolling list near the composer are appended to `document.body` with `position: fixed` (as the Input History picker is) rather than nested in `#send_form` over `#chat`.
- Phone swipe rails (`public/scripts/mobile-swipe-rails.js`) place their chrome as an absolutely positioned sibling; `anchorChrome()` makes the rail's parent `position: relative` when a scroller sits between them. Test rail changes in real WebKit.
- For a new or restyled button, check it with the theme's default accent, a pale accent and a dark accent (Accent Profiles), and measure that the label contrast holds.
- Take screenshots of every visible change whenever possible: phone (393x852) and desktop (1280x900), before and after. Save them in `/screenshots/` at the repo root (git ignores it) and never commit them. Include them in the change report and attach them to the pull request. Open and inspect every screenshot before attaching it, phone first; overflow measurements miss content clipped inside a button. Motion changes get matching before/after GIFs for phone and desktop (Playwright `recordVideo` plus `ffmpeg`), because still screenshots do not show animation. For 'before' builds, extract the old files with `git archive <ref> <paths> | tar -x -C <dir>` and serve them through `context.route`.
- README and handbook screenshots use the default Calico accent unless a change needs another, with test accent profiles reset, and the desktop and phone sets are refreshed together.
- Treat user-visible waiting (startup, navigation, saves, streaming, a reply hidden until Agents finish) as a defect. A real bug found during a task is fixed and verified in the same change; never raise a test timeout to hide it or leave it as a caveat. Ask first only when the fix is destructive or changes what users see.
- Run the unit suite, lint and budgets before calling anything done. Add or update the test that pins the behaviour you changed.
- Never report a guess as a result. Say what was verified, how, and what is inferred.

## Git and attribution

- Commit only when asked, with a local `git commit`.
- Commit subjects and PR titles follow Conventional Commits: `type(optional-scope): subject`, for example `fix(composer): keep Send above the keyboard`.
  - Types: `feat` (new behaviour), `fix` (bug fix), `docs`, `style` (formatting only, no behaviour change), `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.
  - Subject in the lower-case imperative, no full stop, 72 characters at most. Add `!` after the type or scope for a breaking change (`feat(api)!: ...`) and explain the break in the body.
  - PR titles pass the same rule; the `PR Metadata` workflow (`.github/workflows/pr-metadata.yml`) rejects titles that do not.
- Pull requests: one change each, targeting `staging`. Include screenshots for any visible change, phone and desktop, before and after.
- No `Co-Authored-By` trailers, no 'Generated with' footers and no commits made through the GitHub web interface (they record `web-flow` as committer). PR titles and bodies are written by the author, not generated (see `.github/pull_request_template.md`); draft them only on request.
- Never commit `data/`, `.local-runtime/`, `dist/` or secrets. `default/config.yaml` is the template; real config lives outside the repo.
- Keep separate UI changes in separate commits, one per change.
- Never `git stash` in a worktree: the stash list is shared by every worktree, and stashing fails with `git add -N` files. Save a patch (`git diff > <file>.patch`) or use another worktree.
- Dependency changes update `package-lock.json` and `bun.lock` together (`npm install --package-lock-only --ignore-scripts`, then `bun install --lockfile-only`). Pin transitive security fixes in `package.json` `overrides`. Hand-vendored `public/lib/*` files are invisible to `npm audit`.
- `changelog.md` holds only Neconyan history; never restore the inherited upstream history. Merged PRs are listed by `scripts/update-changelog-merged-prs.js`.
- A PR that changes what people see or can do adds one plain-language line under `### Highlights` in the current version's section of `changelog.md` (create the heading above `### Merged Staging PRs` if it is missing). Write it for people using the app, in the voice of the existing Highlights, with UI names in **bold**. Home's **What's new** button shows these lines on staging builds and in releases, and the changelog bot only rewrites `### Merged Staging PRs`, so the line survives.
- Documentation and help links point at the handbook (https://platberlitz.github.io/neconyan-docs/), never `docs.sillytavern.app` (`tests/neconyan-handbook-links.test.js`). Link stable heading ids; a missing topic goes into the handbook first.
- CI: `release-e2e.yml` runs on manual dispatch and on the staging nightly schedule, not on pushes or PRs to `main`. Group 1 and focused runs of `crash-diagnostics.e2e.js` use Ubuntu 22.04 because Chromium never sends the crash event on 24.04, which the rest of the suite uses. Both Playwright images ship Chromium, Firefox, WebKit and their OS libraries; update both pinned image digests and versions together with `tests/package-lock.json` when upgrading Playwright. Only jobs that use Microsoft Edge fetch its checksum-pinned package, without apt. `android-release.yml` is dispatch-only. The Miso bot workflow (`.github/workflows/pr-miso.yml`) runs from the PR head but checks out `.github/miso/merge-bot.cjs` from the base branch, so guard calls to new bot exports (`miso.x?.() ?? oldDefault`) until they reach staging. Match retained browser coverage by test file, title and commit, not by group number.
- Before pushing to staging, fetch the GitHub staging branch and check `git log <fetched>..HEAD`. If it lists commits that are not yours (a local staging branch can hold unpushed work), cherry-pick only your commits onto the fetched staging and push that.
- `.github/miso/labels.json` sets the GitHub label names, colours and descriptions. The PR Manager uses the PR title, changed paths and size; it does not infer labels from branch names. Match issue forms to the names in the catalogue. Preview the repository changes with `node scripts/sync-github-labels.cjs`; after the catalogue is merged to staging, a maintainer can run the same command with `--apply`. It renames labels by editing them in place, keeping assignments, and never deletes a label. The sync keeps names still used by `main` until the same catalogue and automation reach the default branch. Add and verify new blocker names on the target branch before renaming them on GitHub.

## Worktrees

- Give every new worktree its own root `node_modules`. A symlink to another checkout's `node_modules` makes 3 tests fail (`persona-card.test.js` x2, `character-card-metadata-preservation.test.js` x1, 'Requested file path is outside of the server directory') because the PNG library loads its WASM file from outside the checkout and `src/fetch-patch.js` rejects it. Use a hardlinked copy: `cp -al <main checkout>/node_modules node_modules`. `tests/node_modules` may stay a symlink.
- A hardlinked copy is only as current as the checkout it came from. If the server stops at startup with `ERR_MODULE_NOT_FOUND` (seen with `web-push` after it was added to `package.json`), that checkout's packages are older than `package.json`: run `npm ci --no-audit --no-fund` with Node 24 in the worktree, and in the main checkout too so the next copy is complete.
- Those 3 failures always mean the worktree setup is wrong. They are never pre-existing app bugs, so do not report them as a baseline, and do not weaken `fetch-patch.js`. Check `ls -ld node_modules` before running tests.

## Reporting changes

- Lead with what was wrong and what changed, then how it was verified, then caveats.
- Define any unavoidable jargon in the same sentence.
- File paths, function names and commands go in their own section at the end.
- Project copy uses British spelling, single quotes and no em dashes.

- `public/scripts/welcome-screen.js`: workspace rail (desktop sidebar, phone drawer) and the Home panel.
- `public/scripts/neconyan-conversation/`: Conversation mode (timeline, chrome, settings drawer, notifications).

- `public/scripts/neconyan-assistant-tools.js`: assistant tool calls (including character creation with a Quick Image Gen avatar).
- Assistant help: topics in `public/scripts/neconyan-assistant-knowledge/*.js`, selected by `selectAssistantKnowledge` in `public/scripts/neconyan-assistant-knowledge.js`. References are capped at 2048 tokens (UTF-8 bytes in the fallback estimator); the wrapper takes about 560 and one topic can fill the rest, and a topic that no longer fits is dropped, not shortened, so lengthening a topic can silently remove it from its case. An exact key phrase scores +12. Add a topic for each new option, keep a key for the old label when renaming a UI label, and bump the `KNOWLEDGE_REVISION` expectation in `tests/neconyan-assistant-knowledge.e2e.js` (bump again after a rebase if staging took the same number). Focused check: `cd tests && NECONYAN_CONVERSATION_TEST_DISPOSABLE=1 npx playwright test neconyan-assistant-knowledge.e2e.js --grep "refreshed help loads"`.
- A bundled tool needs a `NECONYAN_NATIVE_TOOL_DEFINITIONS` entry, a `NECONYAN_RAIL_TOOL_ROUTES` entry (`welcome-screen.js`) and a sidebar button (`tests/neconyan-rail.test.js`). Full-page tools also need `NECONYAN_TOOL_PAGE_ROUTES` and a `TOOL_PAGES` entry in `public/scripts/neconyan-tool-tour.js`. `.sb-extensions-list` is hidden; tool settings come from `.sb-extensions-tools`.
- Generation: ordinary sends, regenerates and swipes run in the browser; the server job route is used only when forced or required. Generate discards an empty reply (`StreamingProcessor.isEmptyReply`) before Agents and Companions run. `printMessages()` does not redraw Companion cards.
- Agents (`public/scripts/extensions/in-chat-agents/`): `prompt-transform-synthesis.js` and `prompt-transform-refusal.js` are shared by `agent-runner.js` and `src/generation/roleplay-agent-processing.js`. Agent prompts that run on the server need server-safe macros: use `{{mesExamplesRaw}}` rather than `{{mesExamples}}`; Agent-only macros live in `agent-context-macros.js`.
- Bundled Agent templates live in `in-chat-agents/templates/`: one `<slug>.json` per agent (2-space indent), `index.json` (a flat catalogue copy kept in lockstep, 4-space, checked by `tests/in-chat-agents-templates.test.js`), `groups.json` (`grp-*` with `agentTemplateIds`, 4-space) and `regex-bundles.json` keyed by template id (2-space). Category `tracker` is forced to phase `pre`, and bundled trackers ship `companion.includeSystemPrompt: false`. A subcategory must be a key of `AGENT_SUBCATEGORIES`. Bump versions with `node scripts/bump-agent-template-versions.js` (`--dry-run` first). Companion prompts avoid negative wrappers ('Do not', 'Never', 'Output only'), all-caps protocols and the words shape, beat and pressure (the test enforces this). Default-seeded companions go in `DEFAULT_BUNDLED_TEMPLATE_IDS`, and regex-rendered ones also in `BUNDLED_REGEX_POST_DEFAULT_EXCLUDED_TEMPLATE_IDS` (`index.js`). The empty-tracker wording is `TRACKER_EMPTY_OUTPUT_INSTRUCTION` in `companion/companion-shared.js`.
- `public/scripts/macros/` and the MacroEnhanced packs are imported by the server (`src/macros/browser-only.js`, `enhanced.js`), so keep them free of DOM access. An extension's folder name must match its `MODULE_NAME`.
- Catelier (`public/scripts/creator/index.js`): `workspace.edit(op, redraw = false)` does not re-render, so structural edits pass `true`. Text inputs commit on `change`; read `workspace.session.draft` at click time.
- Meower keeps permanent receipts in a private native store; imports, resets and preservation audits must cover it.
- Bundled extensions: `public/scripts/extensions/in-chat-agents` (Agents), `guided-generations`, `input-history`, `neconyan-chats-archive`, `quick-image-gen`, `connection-manager`. Third-party but shipped: `Neconyan-Hopper` (Meower), `Neconyan-Story-Mode`, `Neconyan-BotSearcher`, `Neconyan-Terminal-UI`.
- `src/server-main.js`: Express boot. `src/middleware/basicAuth.js` + `sessionAuth.js`: HTTP basic auth with a 30-day remembered session stored hashed on disk. `src/resumable-generations.js`: replies that outlive the client connection. `src/import-progress.js`: NDJSON progress for data imports.
- `public/scripts/i18n.js` + `public/locales/*.json` (upstream dictionaries) + `public/locales/neconyan/*.json` (generated supplements) + `public/scripts/ui-localization.js` (runtime control labels).
- `default/content/themes/*.json`: bundled themes; `public/scripts/theme-contrast.js` enforces contrast on load. Error pages: `default/content/errors/*.html`.
- Tests: `tests/*.test.js` (Jest), `tests/*.node.js` (node test runner), `tests/*.e2e.js` (Playwright).
- Android: the Node runtime ships small ICU, so `scripts/build-android-payload.js` bundles full ICU data with pinned checksums; match `icu_ver_major` when upgrading Node, and symbolise crashes with `addr2line` on the unstripped `libnode.so`. Compile Java against `android.jar` with `-bootclasspath` (minSdk 30). The payload script copies `android/*.mjs` files one by one, so a new helper needs its own `copyFileSync` line; `npm run lint` skips `android/*.mjs`. `WebView.evaluateJavascript` runs on an `about:blank` base, so use absolute URLs. The app uses legacy packaging (`useLegacyPackaging=true`, `extractNativeLibs=true`): check ZIP 16 KiB offsets only for uncompressed libraries, and check ELF `PT_LOAD` 16 KiB alignment for every library.

## Extension and host code traps

- Reuse existing controls and shared patterns before building new ones.
- `getContext()` copies `characterId` and `chatId` by value, so read it again at each step of long work.
- iOS sends from `touchend` (`bindIOSFastTapSendButton`, `public/scripts/mobile-send-button.js`), so send interceptors capture `touchend` as well as `click`. The host binds Ctrl+Enter to Regenerate on `document`; a handler that owns the shortcut calls `stopPropagation`.
- `saveSettingsDebounced` waits 1 s, so automation waits about 2.5 s before reading saved settings; scripts that edit presets restore and save in `finally`. `enableExtension`/`disableExtension` reload the page by default.
- With no character selected, sending text creates a permanent Assistant chat before slash commands run. `APP_READY` is sticky: late listeners still receive it.
- `deleteCharacter` is not on `getContext()`: call `POST /api/characters/delete`, then `await ctx.getCharacters()`. `/char-delete` closes the open chat first. `--sb-accent-fg` is undefined, so give it a real fallback. `messageFormatting` applies roleplay formatting rules.
- iOS sideways scrollers outside `MOBILE_DOCUMENT_PAN_HORIZONTAL_SCROLL_SELECTOR` can stop the document pan with passive window-capture `touchstart`/`touchmove` listeners that call `stopPropagation` (`installTrendPanGuard` in `Neconyan-Hopper`).
- Settings written by the server: `POST /api/settings/save` rejects stale revisions with 409 `settings_conflict`, so server jobs that write settings return `previousSettingsRevision` and the browser adopts it with `adoptServerSettingsWrite` (`public/script.js`, `tests/settings-server-write-adoption.test.js`).
- Debounced chat and metadata saves record `getChatGeneration()` and give up if it changed. The server rejects destructive saves with 409 `destructive` and accepts append-only saves to a stale slug (`isChatSaveExtension` in `src/endpoints/chats.js`).
- Under Bun an abandoned stream may never emit `close` or `finish`: also listen to `request.aborted`, stay idempotent, never cancel the durable job, and reuse the `onabort` re-arm in `src/resumable-generations.js`. Jest runs on Node, so it does not show this.
- Parallel model calls in one durable job share one `createProviderScope(context)` (`src/jobs/artifacts.js`) as `jobContext.providerScope`, with a `stepNamespace` per reply.
- `public/scripts/a11y.js` overwrites `role` on host classes (`.menu_button`, `.mes_button`, `.inline-drawer-icon`) through a `MutationObserver`, and `keyboard.js` gives `.inline-drawer-icon` `tabindex=0`, so an element carrying those classes ends up with the host's role.
- Listeners that await long work after a reply hold the Send lock (`userInputGenerateMutex`), so defer that work while streaming or while `body.dataset.generating` is set. Don't import `isGenerating` into `agent-runner.js` (`tests/in-chat-agents-send-during-run.e2e.js`).
- Keep optional features out of mandatory startup imports: a content blocker aborting one module (as happened with `push-notifications.js`) breaks the whole import graph. Load them lazily. Import `src/generation/profiles.js` lazily from preset-prompt code, because a static import pulls in `secrets.js`.
- A new static import at the top of `public/scripts/power-user.js` (for example `extension_settings` from `./extensions.js`) broke boot through circular module order (`ReferenceError` on `extensionContextGetter`). Add new imports after the existing ones or use `await import()` at the point of use, and read `pageerror` before assuming a readiness timeout is a slow cold start.
- Bundled extensions load their assets relative to the module: `new URL('./settings.html', import.meta.url).pathname`.

## Release process: staging into main

A release from staging into main covers every step below, including the handbook, assistant help, signed Android downloads, the iPhone IPA and the next staging version.

**Resolve and verify every E2E failure before publishing.** E2E means end-to-end browser or app checks. A pending run or an unresolved test-only failure is not an acceptable release result. Preserve valid passing groups as described in 'Browser CI rerun scope'; record which commits and tests the combined results cover. Keep existing skips visible, and never add skips or weaken assertions to make a release pass.

Inspect every flaky result before promoting the candidate. A passed retry does not prove the cause was fixed. Record the tests that passed only on retry, their run links and what the traces showed in the handover; note the flaky results briefly under 'Checks' in the release notes. Use the issues opened by the nightly workflow to investigate recurring flakes; file one with links to both runs if automation couldn't do so.

1. **Prepare the candidate.** Fetch the remote branches, inspect local changes and check the release history against `package.json`. Use a release worktree so the main checkout stays on `staging`, tracking `origin/staging`, and update that checkout by fast-forward only. Preserve unrelated work. Use the existing normal release version; fixes to an already published `X.Y.Z` use `X.Y.Z.A`. Keep published tags intact. Release preparation does not deploy to any running instance.
2. **Refresh the official handbook.** Review the changes since the previous release in the separate `platberlitz/neconyan-docs` repository. Update the affected guides and their review/version information. Run `.venv/bin/mkdocs build --strict`, `.venv/bin/python scripts/check_site.py` and `.venv/bin/python scripts/browser_check.py` there. Check phone and desktop pages, publish the documentation, wait for Pages to succeed and verify the changed pages on the live site. Historical snapshot versions stay historical.
3. **Refresh the assistants, changelog and README.** Update `public/scripts/neconyan-assistant-knowledge/*.js`, increment `KNOWLEDGE_REVISION`, and add retrieval cases in `tests/neconyan-assistant-knowledge-cases.js`. Keep browser revision expectations in sync. Verify source anchors, topic budgets and retrieval across all nine assistant variants, including focused phone and desktop checks in `tests/neconyan-assistant-knowledge.e2e.js`. Tidy the release's `### Highlights` at the top of `changelog.md` (PRs add them as they land): merge duplicates, fill gaps from the merged-PR list and keep one plain-language line per change, preserving the merged-PR list. Keep the assistant refresh and changelog in separate conventional commits. On staging, update the latest-release line near the top of `README.md` to the version being released and its release-page link, then run `bash scripts/sync-readme-mirror.sh` and `bash scripts/sync-readme-mirror.sh --check` and commit the README update before promoting staging to main. The release-page link will not work until publication; keep the handbook honest about the unpublished candidate. Until publication, `README.md` and `docs/help/about.md` describe it as '<version> staging candidate', checked against the exact source commit and date, and say it is not yet published; update them after publication. Published copy follows the tone in `PRODUCT.md`.
4. **Start browser CI early and run local checks.** Staging pushes do not start release E2E automatically; dispatch `gh workflow run release-e2e.yml --ref staging` once the candidate is on the remote. Run the full unit and Node suites, `npm run test:mewmory`, root and test lint, frontend budgets and `npm run build:frontend`, using Node 24 and the commands above. Run the large local suites one after another. Verify every later fix with the affected checks; retain unaffected results with their original commit and scope.
5. **Resolve failures before the final build.** Read failed logs and retained browser/emulator diagnostics before changing code or retrying. Separate application defects, outdated test fixtures, control timing and runner failures. For unchanged intermittent failures, use `gh run rerun <run-id> --failed`, or `gh run rerun --job <job-id>` for one job. Fixes need a new run at the corrected commit. Select groups with `gh workflow run release-e2e.yml --ref <branch> -f 'shards=[7,8]'`, or give exact test paths with `gh workflow run release-e2e.yml --ref <branch> -f 'files=["tests/panel-look.e2e.js"]'`. Omit both inputs for all 20 groups. Groups are balanced by measured running time (`scripts/release-e2e-groups.js` with `tests/release-e2e-timings.json`); inspect the `release-e2e-plan` artifact for the exact test lists. Refresh the timings from a complete run's job logs with `node scripts/release-e2e-groups.js timings <log-dir>` when groups drift apart. Focused runs do not cancel full runs. A new full dispatch replaces an in-progress full run on the same branch. Watch CI with `gh run watch <run-id> --interval 60 --exit-status`. Keep real crash and security assertions; diagnose missing browsers or platform incompatibilities rather than skipping those checks.
6. **Promote the settled candidate.** Fetch again, inspect the outgoing commits and fast-forward `main` to the intended staging commit, without a merge commit. Apply the staging push checks in 'Git and attribution'. PRs and pushes to `main` do not start another full browser run. Confirm the retained browser results cover the exact candidate before promoting it and record the release commit. If this is the first promotion containing the new GitHub label catalogue, preview and apply `node scripts/sync-github-labels.cjs --apply` after `main` advances to finish the in-place renames.
7. **Build signed Android downloads and the iPhone IPA.** Dispatch `gh workflow run android-release.yml --ref main` and `gh workflow run ios-build.yml --ref main`. These workflows create build artifacts; they do not publish a release. The iPhone build must pass its storage, 13 GiB import, device IPA and simulator startup checks; label simulator verification accurately, without claiming a physical-iPhone test. Require the signed build, WebView fixture and Android 11, 13 and 15 lifecycle/native checks to pass. Inspect failures before retrying; preserve passing jobs when only an unchanged infrastructure failure needs a retry. Label emulator verification accurately, without claiming a physical-phone test. Any later change to the intended release commit requires fresh matching APKs, IPA and source, even if it only changes tests or CI. Finish those corrections before the final build where possible.
8. **Independently verify the twelve release assets.** From a trusted release checkout, run `python3 scripts/verify-release-assets.py build --commit <full-sha> --android-run <run-id> --ios-run <run-id> --directory <new-directory>`. This maintainer command needs Python 3.11 or later, authenticated `gh`, and Android SDK `apksigner` (on `PATH` or supplied with `--apksigner`). It downloads only the successful Android and iPhone artifacts for that commit, checks the exact file sets and all ten checksum entries, verifies the official Android signatures and 16 KiB native alignment, re-runs both platform payload verifiers and compares their provenance, and checks every source ZIP entry against `git archive` (honouring `.gitattributes`). Keep both downloaded folders unchanged for step 9. The verifier never writes to GitHub.
9. **Tag and publish.** Only after all required checks pass, create an annotated `v<version>` tag on that exact commit, with message `Neconyan <version>`, and push it. Publish the GitHub release with `--verify-tag`, all twelve verified assets and release notes under 'What's changed', 'Downloads' and 'Checks'. Write the notes for people using the app, not for auditors: a short opening sentence, then one plain-language bullet per change, each saying what the user can now do or what no longer goes wrong, with no packed bullets listing several features. Keep 'Checks' to three to five short lines (for example browser, unit and server checks; Android and iPhone builds, labelled as emulator and simulator results; asset verification), each linking its run, and state any existing skips or reused browser results in a few words. Run IDs, test counts, retained-group accounting and fix-versus-retry history belong in the step 10 handover entry, not the release page. Report actual results only and do not leave pending placeholders. Run `python3 scripts/verify-release-assets.py published --commit <full-sha> --directory <same-directory>` to confirm the tag, public/latest status, all twelve fresh downloads byte for byte, and GitHub's SHA-256 digests. Keep enough free space for a second copy while this runs.
10. **Start the next staging version and record the result.** Bump the root version in `package.json` and both root entries in `package-lock.json`, plus the expectations in `tests/neconyan-project-boundaries.test.js`. Run the six boundary tests with `npm run test:unit --prefix tests -- --runTestsByPath neconyan-project-boundaries.test.js --maxWorkers=2` and lint that test. Add a dated entry to `docs/server-migration-handover.md` covering the release/tag commit, documentation publication, checks and run IDs, fixes versus unchanged retries, asset verification and next version. Commit and push the bump and handover to staging, then fast-forward the clean main checkout. Check that the README on both `main` and staging names the published release and links to its release page, and run `bash scripts/sync-readme-mirror.sh --check`. If the README mirror workflow adds a commit to main, merge it back into staging so the branches do not diverge. Finish by checking branch/version alignment, clean checkouts and the public release link.

## Deploy recipe (generic)

1. List changed files against the last deployed commit: `git diff --name-only --diff-filter=AM <deployed>..HEAD`; note deletions separately.
2. On the server, tar a backup of exactly those paths before overwriting.
3. Copy the files with rsync over SSH; compare sha256 of the list on both sides.
4. Restart the service and wait for it to bind; an authentication challenge on the root URL means it is up.
5. Fetch a few changed assets through the public URL and check for a marker string from each change.
6. Keep hostnames, paths, keys and credentials out of the repository.
